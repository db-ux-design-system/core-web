# Migration (5.x.x) ➡ 6.0.0

## MCP server & agent CLI: `v2`/`v3` API surface renamed to `generation`-based naming

The consumer-facing identifiers in `@db-ux/mcp-server` and `@db-ux/agent-cli` that used the `v2` / `v3` shorthand have been renamed to spell out the generation. This aligns the tooling with the design-system naming ("DB UX Design System – Generation 3", the current generation, and "DB UX Design System – Generation 2 (aka DB UI)", the previous one). If you reference any of these by name, update them as shown below.

### Renamed MCP tool

<!-- markdownlint-disable MD060 -->

| Before              | After                         | Description                                                                                    |
| ------------------- | ----------------------------- | ---------------------------------------------------------------------------------------------- |
| `scan_v2_migration` | `scan_generation_2_migration` | Update every `callTool` invocation and any `autoApprove` list entry in your MCP configuration. |

`scan_v2_migration` remains registered as a **deprecated alias** that delegates to `scan_generation_2_migration`, so existing installations (whose `mcp.json` launches the floating `npx --yes @db-ux/mcp-server` command) keep working when they pull this release. The alias will be removed in the next major — migrate to `scan_generation_2_migration` now.

<!-- markdownlint-enable MD060 -->

### Renamed `migrate_component` prompt `source_context` values

The documented `source_context` values keep their product prefix but spell out the generation. `source_context` is a free-form string, so only update the value where you pass one of the documented options.

<!-- markdownlint-disable MD060 -->

| Before     | After                |
| ---------- | -------------------- |
| `db-ui-v1` | `db-ui-generation-1` |
| `db-ui-v2` | `db-ui-generation-2` |
| `db-ux-v1` | `db-ux-generation-1` |
| `db-ux-v2` | `db-ux-generation-2` |
| `db-ux-v3` | `db-ux-generation-3` |

<!-- markdownlint-enable MD060 -->

The other values (`bootstrap-4`, `native-html`) are unchanged.

### Renamed exported symbols

If you import from `@db-ux/mcp-server` programmatically, update these names:

<!-- markdownlint-disable MD060 -->

| Before                  | After                            |
| ----------------------- | -------------------------------- |
| `handleScanV2Migration` | `handleScanGeneration2Migration` |
| `scanV2MigrationSchema` | `scanGeneration2MigrationSchema` |

<!-- markdownlint-enable MD060 -->

### Renamed consumer power skill

The migration skill shipped in the `db-ux-consumer-powers` bundle has been renamed, including its folder, its `name`, and the reference in `power.yaml`.

<!-- markdownlint-disable MD060 -->

| Before          | After                     |
| --------------- | ------------------------- |
| `migrate-to-v3` | `migrate-to-generation-3` |

<!-- markdownlint-enable MD060 -->

The skill's shipped path changes accordingly: `skills/migrate-to-v3/SKILL.md` → `skills/migrate-to-generation-3/SKILL.md`. Update any reference that points at the old skill path or identifier. Its user-utterance triggers keep both the new "generation" phrasings and the legacy "v3" ones, so invoking the skill by natural language is unaffected.
