# Migration (5.x.x) ➡ 6.0.0

## MCP server & agent CLI: migration API renamed to the generation naming

The consumer-facing identifiers in `@db-ux/mcp-server` and `@db-ux/agent-cli` that used the old `v2` / `v3` shorthand tokens have been renamed to spell out the generation. This aligns the tooling with the design-system naming: DB UX Design System – Generation 3 is the current generation, and DB UX Design System – Generation 2 (aka DB UI) is the previous one. If you reference any of these identifiers by name, update them as shown below.

### Renamed MCP tool

<!-- markdownlint-disable MD060 -->

| Before              | After                         | Description                                                                                    |
| ------------------- | ----------------------------- | ---------------------------------------------------------------------------------------------- |
| `scan_v2_migration` | `scan_generation_2_migration` | Update every `callTool` invocation and any `autoApprove` list entry in your MCP configuration. |

The old `scan_v2_migration` name is **removed** in this major release — update every `callTool` invocation and `autoApprove` entry to `scan_generation_2_migration`. Installations that launch the floating `npx --yes @db-ux/mcp-server` command will pull this server on their next run, so a stale reference to the old name stops resolving; migrate the name as part of the v6 upgrade.

<!-- markdownlint-enable MD060 -->

### Renamed `migrate_component` prompt `source_context` values

The documented `source_context` values keep their product prefix but spell out the generation. `source_context` is a free-form string, so only update the value where you pass one of the documented options.

<!-- markdownlint-disable MD060 -->

| Before     | After                |
| ---------- | -------------------- |
| `db-ui-v1` | `db-ui-generation-1` |
| `db-ui-v2` | `db-ui-generation-2` |
| `db-ux-v1` | `db-ux-generation-1` |
| `db-ux-v2` | `db-ux-generation-2` |
| `db-ux-v3` | `db-ux-generation-3` |

<!-- markdownlint-enable MD060 -->

The other values (`bootstrap-4`, `native-html`) are unchanged.

### Renamed exported symbol

If you import the scanner handler from `@db-ux/mcp-server` programmatically, update its name:

<!-- markdownlint-disable MD060 -->

| Before                  | After                            |

## Block-level text no longer carries a default `margin-block`

Block-level text elements (`h1`-`h6` and `p`) no longer receive a `margin-block` by default. Previously the default fonts added spacing around every block-level text element; now they are flush unless you opt in.

### How to migrate

To restore the spacing, set `data-text-spacing="true"` on an ancestor element (for example `<html>` or a content container) or on the text element itself. The spacing is `calc(1lh / 2)` on both block edges — derived from each element's own line height rather than a fixed value, so a larger heading gets proportionally more space than a paragraph.

```html
<article data-text-spacing="true">
	<h2>Heading with spacing</h2>
	<p>Paragraph with spacing</p>
</article>
```

If you previously relied on the default spacing everywhere, add the attribute to your root element:

```html
<html data-text-spacing="true"></html>
```

## Headline typography is now part of the required defaults

The DB headline typography for native `h1`-`h6` (the `font` shorthand plus `font-family`, weight and `text-wrap`) moved from the optional `defaults/default-fonts.css` into the required `defaults/default-required.css`. Previously this was optional: importing only the required defaults and omitting the fonts stylesheet left native headings on the user-agent font. That split was unintended — the headline typography has always been meant to be mandatory.

### How to migrate

If you already import `default-fonts.css` (or the full bundle), nothing changes.

If you import only the required defaults and intentionally kept native `h1`-`h6` on your own font, that opt-out no longer exists: native headings now render with the DB headline typography. To keep your own heading font, override it in your own stylesheet after the DB defaults, for example:

```css
h1,
h2,
h3,
h4,
h5,
h6 {
	font: revert;
	font-family: "Your Font", sans-serif;
}
```

## DBHeading: `size` renamed to `visualSize` with new values, `alignment` and `paragraphSpacing` removed

The Heading component family (`DBHeadingH1`-`DBHeadingH6` and `DBCustomHeading`) changed its styling API.

<!-- markdownlint-disable MD060 -->

| Before (v5.x)      | Status |    After (v6.x)     | Description                                                                                                                                      |
| ------------------ | :----: | :-----------------: | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `size`             |   🔁   |    `visualSize`     | Renamed, and its values changed (see below). The attribute changed from `data-size` to `data-visual-size`.                                       |
| `alignment`        |   ❌   |         ❌          | Removed. Set `text-align` directly on the heading element (the component sets `text-align: start`, so an ancestor's `text-align` is overridden). |
| `paragraphSpacing` |   ❌   | `data-text-spacing` | Removed. Block spacing is now controlled by the foundations (see section above).                                                                 |

<!-- markdownlint-enable MD060 -->

### Changed `size` / `visualSize` values

The abstract `3xl`-`3xs` scale is gone. `visualSize` now takes a heading level (`h1`-`h6`) or a paragraph size (`p-small`, `p-medium`, `p-large`). Map the old scale to the matching level:

<!-- markdownlint-disable MD060 -->

| Before (`size`) | After (`visualSize`)                                                        |
| --------------- | --------------------------------------------------------------------------- |
| `xl`            | `h1`                                                                        |
| `lg`            | `h2` (or `p-large`)                                                         |
| `md`            | `h3` (or `p-medium`)                                                        |
| `sm`            | `h4` (or `p-small`)                                                         |
| `xs`            | `h5`                                                                        |
| `2xs`           | `h6`                                                                        |
| `3xl` / `2xl`   | no direct equivalent — both were larger than `h1`; pick `h1` as the nearest |
| `3xs`           | no direct equivalent — smaller than `h6`; pick `h6` or `p-small`            |

<!-- markdownlint-enable MD060 -->

The heading levels `h1`-`h6` map to the former `xl`-`2xs` sizes. The paragraph sizes `p-small`, `p-medium` and `p-large` map to the body font sizes `sm`, `md` and `lg`. The former `3xl`, `2xl` and `3xs` sizes have no direct replacement.

### How to migrate

Rename `size` to `visualSize` and update the value:

```diff
- <DBHeadingH2 size="xl">Heading</DBHeadingH2>
+ <DBHeadingH2 visualSize="h1">Heading</DBHeadingH2>
```

Replace `paragraphSpacing` with the `data-text-spacing` opt-in on an ancestor:

```diff
- <DBHeadingH2 paragraphSpacing>Heading</DBHeadingH2>
+ <div data-text-spacing="true">
+ 	<DBHeadingH2>Heading</DBHeadingH2>
+ </div>
```

For `alignment`, set `text-align` on the heading element itself. The component applies `text-align: start`, so setting it on an ancestor has no effect (we're using inline styles in this example purely for demonstration purposes. Never use inline-styles in your own code):

```diff
- <DBHeadingH2 alignment="center">Heading</DBHeadingH2>
+ <DBHeadingH2 style="text-align: center">Heading</DBHeadingH2>
```

#### `alignment` on `DBCustomHeading`

`DBCustomHeading` is a flex row (the heading plus its `startSlot` / `endSlot` siblings). The removed `alignment` property set both `text-align` on the nested heading **and** `justify-content` on the wrapper, so it also positioned the whole row. `text-align` alone only aligns the text inside the heading and leaves the row start-aligned. To reproduce the old behavior, set `justify-content` on the wrapper (via a `className`/`class`) in addition to `text-align` on the heading:

```diff
- <DBCustomHeading alignment="center">
-   <h2>Installation</h2>
-   <DBButton>More options</DBButton>
- </DBCustomHeading>
+ <DBCustomHeading className="my-centered-heading">
+   <h2>Installation</h2>
+   <DBButton>More options</DBButton>
+ </DBCustomHeading>
```

```css
.my-centered-heading {
	justify-content: center; /* use flex-end for the former alignment="end" */

	h2 {
		text-align: center;
	}
}
```

### Renamed TypeScript exports

The public heading size exports were renamed alongside the property. TypeScript consumers importing them from the package barrel must update both the symbol names and the value union:

<!-- markdownlint-disable MD060 -->

| Before (v5.x)     | After (v6.x)            |
| ----------------- | ----------------------- |
| `HeadingSizeList` | `HeadingVisualSizeList` |
| `HeadingSizeType` | `HeadingVisualSizeType` |

<!-- markdownlint-enable MD060 -->

The value union changed from the abstract `3xl`-`3xs` scale to the heading levels and paragraph sizes listed under "Changed `size` / `visualSize` values" above (`h1`-`h6`, `p-small`, `p-medium`, `p-large`).

```diff
- import { HeadingSizeType } from '@db-ux/react-core-components';
+ import { HeadingVisualSizeType } from '@db-ux/react-core-components';
```

## Renamed CLI executables

The `bin` executables for `@db-ux/mcp-server` and `@db-ux/agent-cli` have been renamed to use a consistent `db-ux-` prefix, avoiding generic names that could collide with other packages.

| Package             | Before       | After              |
| ------------------- | ------------ | ------------------ |
| `@db-ux/mcp-server` | `mcp-server` | `db-ux-mcp-server` |
| `@db-ux/agent-cli`  | `agent-cli`  | `db-ux-agent-cli`  |

### How to migrate

Update any scripts, MCP configurations, or shell commands that reference the old executable names:

```diff
- pnpm exec mcp-server
+ pnpm exec db-ux-mcp-server
```

```diff
- pnpm exec agent-cli
+ pnpm exec db-ux-agent-cli
```

For MCP configuration files (e.g. `.kiro/settings/mcp.json`, VS Code `settings.json`), update the `command` field:

```diff
{
  "mcpServers": {
    "db-ux": {
-     "command": "mcp-server"
+     "command": "db-ux-mcp-server"
    }
  }
}
```
