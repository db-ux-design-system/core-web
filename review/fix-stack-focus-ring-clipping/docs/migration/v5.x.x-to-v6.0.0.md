# Migration (5.x.x) ➡ 6.0.0

## DBStack: no longer a scroll container

`DBStack` no longer sets `overflow: auto`. As a scroll container it clipped to its padding box and therefore cut off the focus ring of its children, which sits outside their border box — in a stack sized to its content the ring was invisible on all four sides.

Content that does not fit a stack is now visible outside of it instead of being scrollable.

### What to change

Only stacks you relied on for scrolling are affected. A stack with `wrap` is unaffected: wrapped items overflow along the cross axis by design, so it keeps the scroll container.

<!-- markdownlint-disable MD060 -->

| Case                                            | Before   | After                                |
| ----------------------------------------------- | -------- | ------------------------------------ |
| Stack whose content exceeds its size            | scrolled | content is visible outside the stack |
| Stack with `wrap`                               | scrolled | unchanged, still scrolls             |
| Focus ring of a child flush with the stack edge | clipped  | fully visible                        |

<!-- markdownlint-enable MD060 -->

If you relied on a stack scrolling, set `overflow` on it yourself:

```css
.my-scrolling-stack {
	overflow: auto;
}
```

Note that a scroll container clips the focus ring of its children. Add `data-focus-container` to reserve the room the ring needs:

```html
<db-stack data-focus-container="true" class="my-scrolling-stack">
	<button type="button">Focusable</button>
</db-stack>
```

### New focus container helper

`data-focus-container` / `.db-focus-container` is available for any clipping container, not just `DBStack`. It reserves the space the focus ring needs outside a child's border box and compensates it with a negative margin, so the surrounding layout is unaffected. See the "Focus Container" example of `DBStack`.
