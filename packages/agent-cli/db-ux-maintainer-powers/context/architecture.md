## 1. Core Toolchain Boundaries

These are the fixed technological boundaries of the system. Do NOT introduce alternatives.

| Layer                    | Technology                                                                                        | Role                                                             | Constraint                                                                                                                                                                                      |
| ------------------------ | ------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Component Compiler**   | [Mitosis](https://github.com/BuilderIO/mitosis) (`@builder.io/mitosis`)                           | Single Source of Truth. All components authored as `*.lite.tsx`. | NEVER edit generated framework artifacts in `output/angular`, `output/react`, `output/vue`, or `output/stencil`.                                                                                |
| **Styling**              | SCSS → PostCSS                                                                                    | Component styles compiled via `sass` + `postcss`.                | Use SCSS variables (`variables.$db-*`) primarily. CSS custom properties (`var(--db-*)`) as fallback only. No hardcoded values.                                                                  |
| **Dev Server / Bundler** | Vite                                                                                              | Development server and build tooling.                            | Config in `packages/components/vite.config.ts`.                                                                                                                                                 |
| **Package Manager**      | pnpm (Workspaces)                                                                                 | Monorepo dependency management.                                  | Use `pnpm install --ignore-scripts` for setup.                                                                                                                                                  |
| **Component Testing**    | Playwright (`@playwright/test`) against the running showcases + Axe-Core (`@axe-core/playwright`) | Interaction, visual regression, and accessibility testing.       | Interaction tests live in `showcases/e2e/<name>/<name>-interaction.spec.ts` and run against every framework showcase (React, Vue, Angular, Stencil). Screenshots/aria/axe run per showcase too. |
| **Web Components**       | Stencil                                                                                           | Output target from Mitosis for Web Component builds.             | Custom Elements Manifest generated via `build:cem` node script.                                                                                                                                 |
| **JS Framework Outputs** | Angular, React, Vue, Stencil                                                                      | Generated by Mitosis from `*.lite.tsx` files.                    | NEVER edit generated artifacts directly. Always modify the `*.lite.tsx` source and regenerate outputs.                                                                                          |

### Mitosis API & Lifecycle Rules

These rules are **invariant** and stem from hard-learned refactoring failures.

| #   | Rule                                                                                                                                               | Rationale                                                                              |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 1   | ❌ NEVER access `_ref` inside `onMount` for DOM operations. Use `onUpdate` with the **initialized-pattern** instead.                               | `_ref` is not guaranteed to be attached when `onMount` fires in all framework outputs. |
| 2   | ❌ NEVER call functions inside JSX property bindings (e.g. `prop={state.fn()}`). Store the computed value in `state` and update it via `onUpdate`. | Function calls in JSX bindings break Mitosis compilation for Angular and Vue outputs.  |
| 3   | ❌ NEVER use getter functions (e.g. `_id() { return ... }`) in `useStore` for derived values. Compute them in `onMount`/`onUpdate`.                | Getter functions produce inconsistent output across frameworks.                        |
| 4   | **State Convention**: Internal state variables MUST use the `_` prefix (e.g. `_active`). NEVER use `internal` as a prefix.                         | Consistent naming convention across all components.                                    |

## 2. Mandatory File Architecture

Every component MUST have this complete file structure. No file may be omitted.

```text
packages/components/src/components/<name>/
├── <name>.lite.tsx                    # Mitosis source (SINGLE SOURCE OF TRUTH)
├── <name>.scss                        # Styles – tokens only, @use variables line 1
├── model.ts                           # TypeScript interfaces (Props, State, VariantList)
├── index.ts                           # Re-export: export { default as DB<Name> } from './<name>';
├── docs/                              # JS Framework-specific documentation
│   ├── Angular.md
│   ├── HTML.md
│   ├── React.md
│   ├── Vue.md
│   └── Migration.md
├── examples/                          # Storybook & Patternhub examples
│   ├── _<name>.arg.types.ts           # Storybook ArgTypes definition
│   ├── default.example.lite.tsx       # Basic usage example
│   ├── variant.example.lite.tsx       # One per feature/variant
│   └── interaction.example.lite.tsx   # Fixture for the cross-framework interaction test (only when the component has user gestures to verify)
├── showcase/                          # Patternhub orchestration
│   └── <name>.showcase.lite.tsx       # Imports all examples, uses shared wrappers
└── agent/                             # AI agent documentation examples
    └── <name>.agent.lite.tsx          # Usage examples for AI code generation

showcases/e2e/<name>/
└── <name>-interaction.spec.ts         # Cross-framework interaction test (React, Vue, Angular, Stencil) — only when the component has user gestures to verify
```

### Critical Path Rules

| File / Folder                                     | Rule                                                                                                                                                                                                                                                                                                                                      |
| ------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `index.ts`                                        | Export path MUST be `./<name>` — WITHOUT `.lite` suffix. Do NOT re-export from `./model`.                                                                                                                                                                                                                                                 |
| `model.ts`                                        | MUST exist. Props MUST be typed. NEVER skip.                                                                                                                                                                                                                                                                                              |
| `<name>.lite.tsx`                                 | MUST exist. This IS the component.                                                                                                                                                                                                                                                                                                        |
| `showcases/e2e/<name>/<name>-interaction.spec.ts` | MUST exist when the component has any user-facing interaction (clicks, keyboard, focus, open/close, value changes, etc). Purely presentational sub-components with no interaction of their own (e.g. `accordion-item`, `badge`, `card`) can rely on the parent's interaction spec plus the existing screenshot/aria/axe coverage instead. |
| `docs/`                                           | MUST exist. Contains framework-specific docs (`Angular.md`, `HTML.md`, `React.md`, `Vue.md`, `Migration.md`). A component without documentation is incomplete.                                                                                                                                                                            |
| `examples/`                                       | MUST exist. Contains at least `default.example.lite.tsx` and the Storybook configuration `_<name>.arg.types.ts`.                                                                                                                                                                                                                          |
| `showcase/`                                       | MUST exist. Contains `<name>.showcase.lite.tsx` to orchestrate the component examples for Patternhub using shared wrappers.                                                                                                                                                                                                               |

| Variant list       | `<ComponentName>VariantList`                                        | `ButtonVariantList`          |
| Variant type       | `<ComponentName>VariantType`                                        | `ButtonVariantType`          |

### Design Tokens – MANDATORY

- NEVER hardcode colors (`#d40000`, `rgb(...)`, `hsl(...)`).
- NEVER use magic numbers for spacing (`margin: 15px`, `padding: 8px`).
- ALWAYS use SCSS variables: `variables.$db-<category>-<scale>` (primary).
- Use CSS Custom Properties `var(--db-<category>-<scale>)` only as fallback when no SCSS variable is available.

#### Token Categories

| Category            | CSS Pattern                       | Scales                                 |
| ------------------- | --------------------------------- | -------------------------------------- |
| Sizing              | `--db-sizing-<scale>`             | 3xs, 2xs, xs, sm, md, lg, xl, 2xl, 3xl |
| Spacing fixed       | `--db-spacing-fixed-<scale>`      | 3xs–3xl                                |
| Spacing responsive  | `--db-spacing-responsive-<scale>` | 3xs–3xl                                |
| Elevation           | `--db-elevation-<scale>`          | sm, md, lg                             |
| Border radius       | `--db-border-radius-<scale>`      | xs, sm, md, lg                         |
| Colors (background) | `--db-*-bg-*`                     | Semantic context-dependent             |
| Colors (text)       | `--db-*-on-bg-*`                  | Semantic context-dependent             |
| Colors (border)     | `--db-*-border-*`                 | Semantic context-dependent             |

### SCSS Rules

1. Every component SCSS file MUST include `@use "@db-ux/core-foundations/build/styles/variables";`. Additional internal helper imports via `@use` are allowed when needed.
2. Component root selector: `.db-<name>`.
3. Use `data-*` attribute selectors for variants: `&[data-variant="brand"]`.
4. Use `variables.$db-*` for SCSS variable access.
5. NEVER use `!important`.
6. Keep nesting shallow and only use additional nesting when it clearly improves readability. Prefer extracting shared/internal styles over deeply nested selectors.
7. NO hardcoded colors, spacings, sizings, or border-radius values, but only SCSS variables provided by Foundations.
8. ❌ NEVER use `border: 0` or `border: none`. ALWAYS use `@extend %transparent-border` for High Contrast Mode support.
9. ⚠️ **RED FLAG**: Overriding `padding`/`font-size` via `[data-density="..."]` means token usage is wrong. Density tokens MUST resolve correctly automatically.
10. **Hover Mixin**: Interactive components MUST use `@include helpers.hover { ... }`. NEVER manually add `cursor: pointer`.
11. **Text Truncation**: Elements using `text-overflow: ellipsis` MUST NOT be a flex child with `overflow: hidden` on a flex container. Switch to `display: block`.
12. **Icon Placement**: Icon `data-` attributes MUST be placed on the interactive root element, NOT on the inner text label `<span>`.
13. Define styles for states via standard selectors or aria-annotations, like e.g. `:disabled` instead of `.disabled` and `[aria-current="page"]` instead of `.active`
14. Do NOT use utility-classes like tailwind.

### TypeScript & Component API

1. Props composition: `DB<Name>DefaultProps` & `GlobalProps` → `DB<Name>Props`.
2. State composition: `DB<Name>DefaultState` & `GlobalState` → `DB<Name>State`.
3. EVERY prop MUST have a JSDoc comment.
4. Variant lists MUST be `as const` arrays with derived union types.
5. **Element ID binding** — Framework compatibility requires: `id={props.id ?? props.propOverrides?.id}`. NEVER use `id={props.id}` alone.

### Accessibility & DOM Rules

These rules protect accessibility compliance and correct DOM semantics.

| #   | Rule                                                                                                                                                                | Rationale                                                                                                                        |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 1   | ❌ NEVER expose dedicated `ariaLabel`, `ariaDescribedby`, etc. props unless internally reused. Frameworks pass these natively.                                      | Custom aria props shadow the framework's built-in attribute forwarding and lead to double-declarations.                          |
| 2   | ❌ NEVER call `event.preventDefault()` in button click handlers unless handling specific form-submissions. Let events bubble.                                       | Calling `preventDefault` swallows the event and breaks parent listeners and framework routing.                                   |
| 3   | **Label Prop**: Props providing an accessible label MUST be named `label`, not `name`. (`name` is reserved for form-grouping.)                                      | `name` has semantic meaning in HTML forms (`<input name="...">`). Using it for labels causes confusion and bugs.                 |
| 4   | **Attribute Cleanup**: Tooltip attribute cleanup (`data-has-tooltip`, `aria-describedby`) MUST be handled in `DBTooltip.onUnMount`, not in the consuming component. | Cleanup responsibility belongs to the component that sets the attribute. Delegating it to consumers creates orphaned attributes. |

## 4. Quality Gate & Invariance

### Absolute Gatekeepers

These commands MUST pass before ANY code is accepted:

```bash
pnpm run build    # Core packages compile without errors
pnpm run test     # All Playwright tests pass (screenshots + a11y)
pnpm run lint     # No linting violations
```

### Testing Rules (Invariant)

Component behavior is tested cross-framework, against the running showcase apps, not by mounting an isolated component instance:

- Interaction tests (clicks, keyboard, focus, open/close, value changes) live in `showcases/e2e/<name>/<name>-interaction.spec.ts` and use `runInteractionTest` from `showcases/e2e/default.ts`. They run against every framework showcase (React, Vue, Angular, Stencil) with a single spec file.
- The fixture the test drives is `packages/components/src/components/<name>/examples/interaction.example.lite.tsx`, wired into `<name>.showcase.lite.tsx` via `LinkWrapperShowcase exampleName="Interaction"`. Give every element under test a `data-testid`.
- Assert on **observable DOM**, never on a JS callback variable — `runInteractionTest` only sees the rendered page. Reflect a callback's effect into the DOM (state + conditional render, or a readout `<span>`) so the test can assert on it.
- Use `content` (already scoped to the requested example via `data-example`) for locators, e.g. `content.getByTestId('click-button')`.
- Use `isVue(process.env.showcase)` / `isAngular(process.env.showcase)` / `isStencil(process.env.showcase)` to branch when a framework genuinely renders different markup for the same behavior (see `// VUE:` comments in migrated specs for precedent).
- Visual regression (`toHaveScreenshot()`), aria-snapshot (`ariaSnapshot()` + `toMatchSnapshot()`), and `@axe-core/playwright` accessibility checks are **not** part of the interaction spec — they already run per showcase page via the existing `*-visual-snapshot.spec.ts` / `*-aria-snapshot.spec.ts` / axe-core suites in `showcases/e2e/`. Do not duplicate them in the interaction spec.
- Sub-components with no interaction of their own (e.g. `accordion-item`) do not need a standalone interaction spec — fold their behavior into the parent's, or rely on the parent's existing e2e coverage.
- **Visual Snapshots**: ALWAYS add a comment explaining WHY a custom ratio tolerance was set in snapshot tests.

### Forbidden Patterns (Invariant)

These patterns are NEVER acceptable. Violations trigger immediate rejection.

| Pattern                                                    | Violation                                                                                                                                                                                                                        |
| ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Inline styles with pixel values                            | Use SCSS variables (`variables.$db-*`) or CSS custom properties (`var(--db-*)`) exclusively.                                                                                                                                     |
| Invented icon names                                        | ALWAYS call `list_icons` tool via MCP first.                                                                                                                                                                                     |
| Editing generated files in `output/`                       | Generated framework artifacts in `output/angular`, `output/react`, `output/vue`, and `output/stencil` must not be edited directly. Update source files and regenerate.                                                           |
| Skipping `model.ts`                                        | Props MUST be typed. No exceptions.                                                                                                                                                                                              |
| Export from `./<name>.lite`                                | Export from `./<name>` WITHOUT `.lite` suffix.                                                                                                                                                                                   |
| Re-exporting `./model` in `index.ts`                       | Do NOT re-export model.                                                                                                                                                                                                          |
| Missing foundations variables import in SCSS               | Component SCSS files MUST include `@use "@db-ux/core-foundations/build/styles/variables";`. Additional internal helper `@use` imports are allowed.                                                                               |
| Hardcoded colors/spacings in SCSS                          | EVERY value MUST be a token.                                                                                                                                                                                                     |
| Guessing Figma specs                                       | ABORT without Figma URL. Query Figma MCP.                                                                                                                                                                                        |
| Skipping the interaction spec for an interactive component | `showcases/e2e/<name>/<name>-interaction.spec.ts` is mandatory whenever the component has clicks, keyboard input, focus, open/close, or value-change behavior.                                                                   |
| Asserting on a JS callback variable in an interaction test | The test only sees the rendered showcase page. Reflect the callback's effect into observable DOM instead.                                                                                                                        |
| Missing `propOverrides?.id`                                | Use `props.id ?? props.propOverrides?.id`. Always.                                                                                                                                                                               |
| `border: 0` or `border: none`                              | Use `@extend %transparent-border` for HCM support.                                                                                                                                                                               |
| `cursor: pointer` without mixin                            | Use `@include helpers.hover { ... }` instead.                                                                                                                                                                                    |
| Redundant `aria-disabled` on native `<button>`             | Do not add `aria-disabled` when native `disabled` already communicates the state. `aria-disabled` is allowed for intentional soft-disable patterns that remain keyboard-accessible (for example to keep tooltip help reachable). |
| Function calls in JSX bindings                             | Store in `state`, update via `onUpdate`.                                                                                                                                                                                         |
| `_ref` access in `onMount`                                 | Use `onUpdate` with initialized-pattern.                                                                                                                                                                                         |
| Excluding files in storybook config                        | Fix the example to be Mitosis-compatible.                                                                                                                                                                                        |
