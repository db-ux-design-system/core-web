# DBButton

> **Prototype for discussion.** This page bundles the developer documentation of a component in one place. Each section names its source. If the structure is agreed on, the page is generated for every component.

Buttons initiate actions and confirm decisions. Use them to guide users through key tasks and flows.

- Trigger an action (e.g. Send, Save, Delete)
- Indicate that interaction or confirmation is expected
- Highlight a primary or secondary action

## Accessibility

- DBButton renders a native `<button>`: focus, keyboard activation and the disabled state come from the browser.
- Without `type`, the button is `button` if it has `onClick` or `commandfor`, otherwise `submit`. Set `type` explicitly inside forms.
- Icon only (`noText`): the text is the accessible name. Never leave it empty.
- The small button in functional density is 20 px high. Keep a clickable area of at least 24 × 24 px with surrounding space, and don't let other controls overlap it.

_Source: behaviour from `button.lite.tsx` and `_button-components.scss`, target size from the platform guideline "Accessibility". New on this page._
